The Problem


Manual loan review is slow & inconsistent

  • Reviewer reads 20-page policy PDF manually
  • Checklist compliance varies between reviewers
  • Missing documents caught late in the process
  • Fraud signals require specialist knowledge

AI alone is risky for financial decisions

  • LLMs hallucinate policy requirements
  • No audit trail for regulators
  • Prompt injection can manipulate approval guidance
  • One model can't specialize in everything

The Goal

AI that assists human reviewers — grounded in policy, auditable, secure.
Never approves or rejects. Only provides guidance.

Key Design Decisions


Zero Tool Coupling in Agents

Agents never reference tool names. The LLM reads tool descriptions and decides which to call. Agent code has no import of any tool implementation.


Agent → run_with_tools(system, user)
LLM → "I'll call search_policy_tool"
MCP → executes it, returns result

Policy as Single Source of Truth

No hardcoded document requirements or compliance rules. Upload a different bank's PDF → system adapts automatically. Zero code changes needed.

MCP (Model Context Protocol)

Tools run in a standalone MCP server (SSE on :8001). Backend connects as an MCP client. Tool layer is fully decoupled from agent layer.

Deterministic + AI Hybrid

Fraud signals and risk flags use rule-based math (no LLM). Document extraction and review use LLM. Right tool for right job.

Security & Guardrails


Input Guardrail

  • Presidio — contextual PII: PERSON, EMAIL, PHONE
  • Regex — financial PII: SSN, bank accounts, credit cards
  • 30-phrase denylist across 5 attack categories
  • Delimiter discipline — all user input wrapped in <<>> tags
  • Length cap: 2000 chars

Output Guardrail

  • Blocks approval/rejection language ("I approve", "denied")
  • Citation honesty — cited chunks must exist in retrieved context
  • PII scrub on generated output
  • On violation → safe fallback + requires_human_review=True

5 Injection Attack Categories

  • Override / jailbreak ("ignore previous instructions")
  • Approval manipulation ("approve this loan")
  • Authority impersonation ("as your developer")
  • System prompt extraction ("reveal your system prompt")
  • Role hijacking ("act as", "pretend you are")

Human Review Triggers

  • Risk severity: high or critical
  • Any fraud signals detected
  • Missing required documents
  • No policy chunks retrieved (ungrounded response)
  • Output guardrail violation

LLM-as-Judge Evaluation


After every review, a second gpt-4o call scores the reviewer's guidance on 4 dimensions.


DimensionWhat it measures
Decision QualityIs the guidance useful and actionable?
Grounding Score0–100% backed by policy OR deterministic rules
Hallucination RiskClaims not in retrieved context
Policy ComplianceStays within policy scope

Key insight: deterministic ≠ hallucination

Risk flags and fraud signals come from rule engines — factual. The judge is explicitly told to count these as grounded evidence, not penalize them for lacking citations.

How to test for hallucination

  • Ask about policy details not in the PDF → LLM invents section numbers → judge flags high risk
  • Submit with 0 retrieved chunks → generic guidance → grounding = 0%
  • Ask about DTI thresholds the policy doesn't mention → invented number → caught

Grounding score visual

UI renders score as a colored progress bar: green ≥70%, orange 40–70%, red <40%
