IK Capstone Project — Week 1

The Problem

Human loan reviewers face compounding challenges at scale.

1 — Policy Volume Overload

Reviewing hundreds of applications against complex, frequently-updated policy documents. Manual cross-referencing is slow, error-prone, and inconsistent across reviewers.

2 — Missing Documents Waste Review Cycles

Applications move through the queue before anyone checks completeness. Reviewers spend time on files that will be sent back anyway.

3 — Risk Signals Buried in Raw Data

High-risk patterns — extreme debt-to-income ratios, inconsistent income evidence, fraud signals — require synthesis across multiple data points. Reviewers need conclusions, not spreadsheets.

"The system never approves or rejects — it provides grounded guidance so humans can decide with confidence."

LangGraph State — How Agents Share Memory

LoanReviewState is a TypedDict that flows through all 9 nodes. Each node receives the full state, returns a partial dict, and LangGraph merges it automatically.

class LoanReviewState(TypedDict): # Input application_id: str loan_application: LoanApplication # Per-agent outputs (each agent writes its own slice) sanitized_input: SanitizedInput # InputGuardrail plan: Plan # PlannerAgent retrieved_context: RetrievedContext # RetrievalAgent doc_check_result: DocCheckResult # DocCheckAgent risk_assessment: RiskAssessment # RiskReviewAgent fraud_signals: FraudSignals | None # FraudDetectionAgent reviewer_guidance: ReviewerGuidance # ReviewerAgent guardrail_result: GuardrailResult # OutputGuardrail evaluation: Evaluation # EvaluationAgent # Append-only lists (Annotated merge) agent_trace: Annotated[list[TraceEntry], operator.add] guardrails_applied: Annotated[list[str], operator.add]

Append-Only Lists

  • agent_trace — accumulates TraceEntry from every node (agent, started_at, finished_at, summaries)
  • guardrails_applied — accumulates guardrail tags without any node overwriting another's record
  • Annotated[list, operator.add] tells LangGraph to concatenate, not replace

"No shared variables, no pub/sub, no message queues — just a dict that grows."

  • Merge pattern is deterministic and testable
  • Any node can read any prior agent's output
  • Full audit trail is in the state — no external log needed

Defense in Depth: Input & Output Guardrails

Two independent guardrail layers — neither alone is sufficient.

InputGuardrail

  • Length cap — 2 000 chars max; excess is truncated before any LLM sees it
  • Financial PII regex — SSN, bank account, credit card → [REDACTED:TYPE]
  • Presidio NLP — PERSON, EMAIL, PHONE detected and redacted
  • Injection denylist — 30 phrases across 5 categories (prompt override, jailbreak, system manipulation, role-play, data exfiltration)
  • Delimiter discipline — user content wrapped in <<<USER_QUESTION>>> markers before LLM calls

OutputGuardrail

  • Forbidden phrases — word-boundary regex for "approved", "denied", "rejected" (skips "not approved" — context-aware)
  • Citation honesty — every [Source: X, chunk N] must be traceable to retrieved_context; hallucinated citations are caught
  • PII scrub — same financial regex pass on LLM output before it leaves the system
  • On violation — safe fallback response, sets requires_human_review=True, no silent retry

Guardrail violations surface in guardrails_applied (append-only) and in the final LoanReviewResponse — never silently swallowed.

Agents Deep Dive — Specialist Agents

RetrievalAgent MCP LLM

  • LLM generates semantic query from loan context
  • Calls search_policy_tool via MCP → Pinecone top-K chunks
  • Returns Citation objects: chunk text + source + score
  • All downstream agents can cite these chunks

DocCheckAgent MCP LLM

  • Calls get_submitted_documents_tool — what was actually uploaded
  • Calls extract_requirements_tool (LLM) — what policy requires for this loan type
  • Compares submitted vs. required
  • Returns missing / present lists + completeness flag

RiskReviewAgent Rule

  • Pure rule-based — no LLM, fully deterministic
  • 5 risk flags: income_ratio, low_credit, missing_income_evidence, zero_income, no_docs
  • Outputs severity level: LOW / MEDIUM / HIGH
  • Feeds the conditional routing decision

FraudDetectionAgent MCP Rule

  • Calls check_fraud_signals_tool via MCP — deterministic threshold math, no LLM
  • Signals: income_mismatch_ratio, loan_to_income_extreme, employment_income_conflict, suspicious_round_numbers
  • Only fires when routed by should_run_fraud() conditional edge
  • Returns FraudSignals with flag list + severity — None if skipped

Smart Routing — Run Only What's Needed

PlannerAgent sets intent; LangGraph conditional edges enforce it.

Always Runs (Every Request)

  • InputGuardrail
  • PlannerAgent
  • Parallel Specialists (Retrieval, DocCheck, RiskReview)
  • ReviewerAgent
  • OutputGuardrail
  • EvaluationAgent

Conditionally Runs: FraudDetection

Triggers when any of:

  • Loan amount > threshold (high loan)
  • High income ratio flag from RiskReviewAgent
  • Zero income detected
  • Employment type = self_employed

"Rule-based routing is cheaper, faster, and testable compared to LLM-based routing."

How the Conditional Edge Works

After the parallel specialists node completes, should_run_fraud(state) inspects risk_assessment.flags alongside the raw loan fields. LangGraph routes to fraud_detection_node or skips directly to reviewer_node — no if/else inside any agent.

Three tables. Two access paths. Agents never import db/ directly.

Core loan data: applicant info, loan amount, type, income, employment, credit score, debt

submitted_documents

Document records linked to application_id: doc type, filename, upload timestamp

review_records

Persisted LoanReviewResponse + full agent_trace JSON — every review is auditable

Access Path 1 — FastAPI Routes

  • FastAPI route handlers use get_session dependency injection
  • SQLModel ORM — type-safe queries
  • Used for CRUD endpoints: seed data, fetch applications, store reviews

Access Path 2 — Agents via MCP

  • Agents call get_loan_application_tool and get_submitted_documents_tool
  • MCP server owns the DB connection — agents are stateless
  • Enforces separation: agent logic ≠ data access logic

Design Decisions

  • Uses gpt-4o with temperature=0 for reproducible scoring
  • Scores both the real answer and the safe fallback — the fallback also needs to be evaluated
  • Rule-engine outputs (risk flags, fraud signals) are counted as grounded — they are not hallucinations, they are deterministic computations
  • Evaluation results persisted in review_records for longitudinal quality tracking
  • Minimum eval suite: 5 cases including at least 1 injection attempt

Evaluation runs inside the graph — not as an offline batch job — so every production response is scored.

LoanFlow AI

Guidance-first. Policy-grounded. Auditable.

1 — LangGraph State = Shared Memory

No message bus, no shared variables. A TypedDict that grows — each node writes its slice, LangGraph merges deterministically.

2 — MCP Decouples Tool Logic from Agent Logic

Agents call tools by name via SSE. Pinecone, SQLite, or rule math can be swapped without touching agent code.

3 — Guardrails Are Defense in Depth

Input and output layers catch different threat classes. Neither alone is sufficient. Both log to immutable state.
